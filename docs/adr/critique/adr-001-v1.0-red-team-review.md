## Implementation Blockers

### Blocker 1: `cross_references` Key Naming is Ambiguous (The "Junior Dev" Test)

**Section:** 4 (Agentic Biolink Schema)

**The Problem:**
```json
"cross_references": {
  "ensembl": "ENSG00000012048",
  "uniprot": "P38398",
  "chembl": "CHEMBL3712877"
}
```

If I hand this to three developers, I will get three different implementations:

| Developer | UniProt Key | Ensembl Value |
|-----------|-------------|---------------|
| Dev A | `uniprot` | `ENSG00000012048` (gene) |
| Dev B | `uniprotkb` | `ENST00000357654` (transcript) |
| Dev C | `uniprot_accession` | `["ENSG00000012048", "ENST00000357654"]` |

**Specific Ambiguities:**
1. Is the key `uniprot`, `uniprotkb`, or `uniprot_accession`?
2. Is `ensembl` the gene ID (`ENSG`) or transcript ID (`ENST`)? Both are valid Ensembl IDs.
3. What about `entrez`? It was in the original strategy but is missing from the example.
4. Are values **always strings** or can they be **arrays** (for genes with multiple UniProt isoforms)?
5. What if a cross-reference doesn't exist for an entity? Is the key omitted, or set to `null`?

**Required Clarification:**
Provide a normative **Cross-Reference Key Registry** table:

| Key Name | ID Type | Format | Cardinality | Required |
|----------|---------|--------|-------------|----------|
| `ensembl_gene` | Ensembl Gene ID | `ENSG[0-9]{11}` | Single | Yes |
| `ensembl_transcript` | Ensembl Transcript ID | `ENST[0-9]{11}` | Array | No |
| `uniprot` | UniProt Accession | `[A-Z0-9]{6,10}` | Array | Yes |
| `entrez` | NCBI Gene ID | `[0-9]+` | Single | Yes |
| `chembl` | ChEMBL Target ID | `CHEMBL[0-9]+` | Single | No |

### Blocker 2: Pagination Response Envelope Undefined (The Pagination Gap)

**Section:** 5 (Tool/Resource Bifurcation)

**The Problem:**
The ADR says "Cursor-based pagination required" but does not define:
1. The response envelope structure
2. The cursor key name
3. How to signal "no more pages"
4. Whether total count is provided

**Risk:** My HGNC developer will implement:
```json
{"data": [...], "next": "abc123"}
```

My ChEMBL developer will implement:
```json
{"results": [...], "pagination": {"cursor": "xyz789", "has_more": true}}
```

The agent will fail to generalize across tools.

**Required Clarification:**
Define a **Canonical Pagination Envelope**:

```json
{
  "items": [...],           // Always "items"
  "pagination": {
    "cursor": "opaque_string" | null,  // null = no more pages
    "total_count": 1234 | null,        // null if unknown
    "page_size": 50
  }
}
```

### Blocker 3: Error Response Schema Undefined (Failure Mode Spec)

**Section:** 3 (Fuzzy-to-Fact Protocol)

**The Problem:**
The ADR says:
> "It must throw an error instructing the agent to 'Resolve the entity first'."

But "throw an error" is not a spec. My developers will ask:
- HTTP status code? (400? 422? 200 with error body?)
- JSON structure? (Freeform string? Structured object?)
- Error codes for programmatic handling?

**Risk:** If errors are unstructured, the agent cannot programmatically recover. It will either:
1. Crash and surface the raw error to the user
2. Hallucinate a workaround instead of calling the resolution tool

**Required Clarification:**
Define a **Canonical Error Envelope**:

```json
{
  "success": false,
  "error": {
    "code": "UNRESOLVED_ENTITY",
    "message": "The input 'BRCA1' is not a resolved CURIE.",
    "recovery_hint": "Call 'resolve_gene' with the input first.",
    "suggested_tool": "resolve_gene",
    "invalid_input": "BRCA1"
  }
}
```

And define the **Error Code Registry**:

| Code | Meaning | Recovery Action |
|------|---------|-----------------|
| `UNRESOLVED_ENTITY` | Raw string passed to strict tool | Call resolution tool |
| `ENTITY_NOT_FOUND` | CURIE does not exist in source | Verify CURIE is correct |
| `RATE_LIMITED` | Upstream API throttled | Retry with exponential backoff |
| `AMBIGUOUS_QUERY` | Fuzzy search returned 0 or 100+ results | Refine query |

### Blocker 4: Token Budget Risk Assessment Missing (Token Budgeting)

**Sections:** 4 and 5

**The Problem:**
We added `gene_groups`, `aliases`, `previous_symbols`, and `cross_references` to every entity. The "50 items per page" limit was set before this enrichment.

**Calculation:**

| Field | Est. Tokens (per entity) |
|-------|-------------------------|
| `subject_id` | 8 |
| `subject_name` | 5 |
| `subject_aliases` (avg 3) | 15 |
| `previous_symbols` | 5 |
| `subject_location` | 5 |
| `gene_groups` | 12 |
| `cross_references` (4 keys) | 35 |
| `relation` + `object_*` | 25 |
| `evidence_score` | 3 |
| **Total per entity** | **~115 tokens** |

**Page Cost:** 50 items × 115 tokens = **5,750 tokens per page**

**Multi-hop Scenario:**
```
Step 1: resolve_genes(["BRCA1", "TP53", ...]) → 10 genes × 115 = 1,150 tokens
Step 2: get_targets_for_genes(10 genes) → 50 targets × 115 = 5,750 tokens
Step 3: get_drugs_for_targets(50 targets) → 50 drugs × 115 = 5,750 tokens
Accumulated context: 12,650 tokens
```

This is manageable for Claude's 200k window, but it crowds out:
- System prompt (~4k)
- Conversation history
- Reasoning space

**Risk:** For complex queries, the agent may hit context limits or degrade reasoning quality.

**Required Clarification:**
1. Should we define a **"Slim" response mode** for batch operations? (IDs + names only, no cognitive hooks)
2. Should the page size be **dynamic** based on schema richness? (e.g., 50 for slim, 20 for full)
3. Should we add a `fields` parameter to let the agent request only needed attributes?

## Appendix: Proposed Schema Definitions

### A. Cross-Reference Key Registry (Proposed)

```python
from typing import Optional
from pydantic import BaseModel, Field

class CrossReferences(BaseModel):
    """Standardized cross-reference IDs for triangulation."""

    ensembl_gene: str = Field(
        ...,
        pattern=r"^ENSG\d{11}$",
        description="Ensembl Gene ID"
    )
    ensembl_transcript: Optional[list[str]] = Field(
        default=None,
        description="Ensembl Transcript IDs (ENST...)"
    )
    uniprot: list[str] = Field(
        ...,
        min_length=1,
        description="UniProt accession(s) - array to handle isoforms"
    )
    entrez: str = Field(
        ...,
        pattern=r"^\d+$",
        description="NCBI Entrez Gene ID"
    )
    chembl: Optional[str] = Field(
        default=None,
        pattern=r"^CHEMBL\d+$",
        description="ChEMBL Target ID (if exists)"
    )
```

### B. Pagination Envelope (Proposed)

```python
from typing import TypeVar, Generic, Optional
from pydantic import BaseModel

T = TypeVar('T')

class Pagination(BaseModel):
    cursor: Optional[str] = Field(
        default=None,
        description="Opaque cursor for next page. null = no more pages."
    )
    total_count: Optional[int] = Field(
        default=None,
        description="Total items matching query. null if unknown."
    )
    page_size: int = Field(
        default=50,
        le=50,
        description="Items per page (max 50)"
    )

class PaginatedResponse(BaseModel, Generic[T]):
    items: list[T]
    pagination: Pagination
```

### C. Error Envelope (Proposed)

```python
from typing import Optional
from pydantic import BaseModel
from enum import Enum

class ErrorCode(str, Enum):
    UNRESOLVED_ENTITY = "UNRESOLVED_ENTITY"
    ENTITY_NOT_FOUND = "ENTITY_NOT_FOUND"
    RATE_LIMITED = "RATE_LIMITED"
    AMBIGUOUS_QUERY = "AMBIGUOUS_QUERY"
    INVALID_CURIE = "INVALID_CURIE"
    UPSTREAM_ERROR = "UPSTREAM_ERROR"

class ErrorDetail(BaseModel):
    code: ErrorCode
    message: str
    recovery_hint: str
    suggested_tool: Optional[str] = None
    invalid_input: Optional[str] = None

class ErrorResponse(BaseModel):
    success: bool = False
    error: ErrorDetail
```
